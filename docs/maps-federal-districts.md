# Офлайн-карты России по федеральным округам

**Этап 2.3 — разведка и план. Код не менялся.** Этот документ — единственный добавленный файл.

Цель этапа: понять, как сейчас устроены офлайн-карты в «Ковчеге», и предложить план нарезки России на 8 федеральных округов (ФО) так, чтобы файлы можно было раздавать без Git LFS и подключать текущим механизмом загрузки.

> Документ лежит в корне `docs/`. Встроенная документация приложения читает `admin/docs/`, поэтому в `/docs` он не появится без отдельного копирования. Это осознанно: здесь проектное решение, а не пользовательская инструкция.

---

## 0. Короткие выводы

1. **Сейчас есть два разных пути карт.** Курируемые файлы лежат в `collections/maps.json` и скачиваются готовыми PMTiles из апстрим-репозитория `Crosstalk-Solutions/project-nomad-maps`. Глобальная карта и страны/континенты режутся на месте из планетарного билда Protomaps через `pmtiles extract`.
2. **`admin/constants/map_regions.ts` — это не реестр регионов.** Там только лимиты зумов, имя мирового тайла и сборщик аргументов CLI. Списка ФО или субъектов РФ в коде нет; его нужно создать.
3. **Главный блокер — жёстко зашитые URL апстрима.** И `collections/maps.json`, и каталог обновлений карт читаются из `Crosstalk-Solutions/...`, а не из форка. Пока это не исправлено, добавление записей в локальный `maps.json` не доедет до установленных клиентов.
4. **Рекомендуемая схема:** 8 готовых PMTiles-файлов (по одному на ФО), границы — из OSM (`admin_level=3/4`, ODbL), нарезка — `pmtiles extract` из планетарного билда Protomaps. Основной хостинг — объектное хранилище (R2/S3-совместимое), GitHub Releases — только для вариантов z10/z12, где файлы заведомо меньше 2 ГиБ. Git LFS не использовать.
5. **Оценка суммарного объёма z15 — около 21 ГБ** (диапазон примерно 12–32 ГБ), z12 — около 2,7 ГБ. Это модельная оценка, а не измерение: перед публикацией нужно прогнать `pmtiles extract --dry-run` по каждому ФО и записать реальные байты в `size_mb`.

## 1. Как офлайн-карты устроены сейчас

### 1.1. Курируемые PMTiles из `maps.json`

Файл [`collections/maps.json`](../collections/maps.json) — версионированный каталог курируемых карт (`spec_version: "2026-02-11"`). Сейчас в нём 9 коллекций (штаты США). Каждый ресурс имеет поля:

- `id` — стабильный идентификатор (например, `california`);
- `version` — `YYYY-MM` (например, `2025-12`);
- `title`, `description`;
- `url` — прямой URL на `.pmtiles`;
- `size_mb` — заявленный размер (в коде умножается на `1024 * 1024`, то есть фактически MiB).

Пример URL из [`collections/maps.json`](../collections/maps.json):

```text
https://github.com/Crosstalk-Solutions/project-nomad-maps/raw/refs/heads/master/pmtiles/california_2025-12.pmtiles
```

Файлы — региональные производные [Protomaps Basemap](https://docs.protomaps.com/basemaps/downloads), нарезанные апстримом. В README репозитория `project-nomad-maps` прямо сказано: производные созданы командой `pmtiles extract` по региональным GeoJSON, а GeoJSON для штатов США собран из TIGER/Line. То есть **апстрим режет готовые файлы заранее**, а «Ковчег»/NOMAD их только скачивает.

За загрузку отвечает [`MapService.downloadCollection()`](../admin/app/services/map_service.ts) (строки ~136–193):

1. получает спецификацию через `CollectionManifestService.getSpecWithFallback('maps')`;
2. находит коллекцию по `slug`;
3. отбрасывает ресурсы, у которых `id` уже есть в `InstalledResource` с `resource_type = 'map'`;
4. для каждого оставшегося ресурса проверяет URL через `assertNotPrivateUrl`, делает имя файла из последнего сегмента URL и ставит задачу `RunDownloadJob.dispatch()`;
5. файл кладётся в `storage/maps/pmtiles/<filename>`, а `resourceMetadata` создаёт/обновляет запись `InstalledResource`.

Важно: фильтр «уже установлено» сравнивает **только `id`, не версию**. Если в манифесте появится `california` версии `2026-01` вместо `2025-12`, карточка коллекции всё равно будет считать ресурс установленным. Обновления идут отдельным путём — через `CollectionUpdateService` и каталог `KiwixCatalogService` (см. 1.4).

Имя файла курируемого ресурса должно оканчиваться на `_YYYY-MM.pmtiles`: на этом построены:

- [`CollectionManifestService.parseMapFilename()`](../admin/app/services/collection_manifest_service.ts) (строки ~408–413);
- [`reconcileFromFilesystem()`](../admin/app/services/collection_manifest_service.ts) (строки ~493–542) — восстановление `InstalledResource` по файлам на диске при старте;
- поиск обновлений в [`KiwixCatalogService.pickNewestMap()`](../admin/app/services/kiwix_catalog_service.ts) (строки ~266–283), регулярка `^<id>_(\d{4}-\d{2})\.pmtiles$`.

### 1.2. Глобальная карта и извлечение по странам

Второй путь — скачать/нарезать из планетарного билда Protomaps:

- [`MapService.getGlobalMapInfo()`](../admin/app/services/map_service.ts) (строки ~639–661) запрашивает `https://build-metadata.protomaps.dev/builds.json`, берёт самый свежий ключ и строит URL `https://build.protomaps.com/<YYYYMMDD>.pmtiles`. Полный планетарный файл — примерно 120 ГБ, z0–15 (по документации Protomaps).
- [`MapService.downloadGlobalMap()`](../admin/app/services/map_service.ts) (строки ~663–707) может скачать его целиком.
- [`MapService.extractRegion()`](../admin/app/services/map_service.ts) (строки ~766–840) режет область по списку стран. Границы стран берутся из Natural Earth `ne_50m_admin_0_countries.geojson` в [`CountriesService`](../admin/app/services/countries_service.ts); полигоны буферизуются на `0.1°` (`REGION_BUFFER_DEGREES`), чтобы прибрежные тайлы не выпадали. Результат — файл `<slug>_<YYYYMMDD>_z<maxzoom>.pmtiles`.
- Перед нарезкой [`MapService.extractPreflight()`](../admin/app/services/map_service.ts) (строки ~717–764) делает `pmtiles extract --dry-run` и пытается распарсить «archive size»/«tiles» из вывода. Парсер намеренно «мягкий»: формат вывода CLI нестабилен, при неудаче оценка просто не показывается.
- Сама нарезка — [`RunExtractPmtilesJob`](../admin/app/jobs/run_extract_pmtiles_job.ts): `spawn` бинарника `pmtiles`, аргументы `extract`, `--region`, `--maxzoom`, `--download-threads=8`, `--overfetch=0.2`; прогресс считается по размеру выходного файла; по завершении создаётся `InstalledResource`, старый файл и «осиротевшие» файлы с тем же префиксом удаляются.
- Аргументы CLI собирает [`buildPmtilesExtractArgs()`](../admin/constants/map_regions.ts). Бинарник `pmtiles` ставится в образ Dockerfile (версия `1.30.2`, путь `/usr/local/bin/pmtiles`), см. [`Dockerfile`](../Dockerfile) (строки ~48–70).

### 1.3. Как пользователь выбирает регион/страну

Страница настроек [`admin/inertia/pages/settings/maps.tsx`](../admin/inertia/pages/settings/maps.tsx):

- **Curated Map Regions** — карточки коллекций из `maps.json`. Клик по карточке открывает подтверждение и вызывает `downloadCollection(slug)`, то есть скачивает **всю коллекцию целиком**. Выбрать отдельный ресурс внутри коллекции нельзя.
- **Download by country or region** — кнопка «Choose Countries» открывает [`CountryPickerModal`](../admin/inertia/components/CountryPickerModal.tsx). Внутри:
  - список стран из `/api/maps/countries` (Natural Earth), сгруппированный по континентам;
  - поиск по английскому/русскому названию и ISO-коду;
  - «quick picks» — континенты из `/api/maps/country-groups`;
  - слайдер `maxzoom` от 0 до 15 (по умолчанию 15);
  - автоматический preflight с дебаунсом 1,5 с; при изменении выбора/зума уходит `POST /api/maps/extract-preflight`;
  - кнопка старта вызывает `POST /api/maps/extract` с `countries`, `maxzoom`, `estimatedBytes`;
  - бейдж «Installed» вычисляется по именам файлов регуляркой `^([a-z]{2})_[\w-]+_z\d+\.pmtiles$`.
- **Download a Custom Map File** — вставка произвольного URL `.pmtiles` с preflight (HEAD).
- **Stored Map Files** — таблица файлов из `storage/maps`, удаление.
- **Global Map** — баннер с предложением скачать полный планетарный файл.

Отдельного выбора «федеральный округ» или «субъект РФ» в UI **нет**.

Просмотр карты — [`admin/inertia/pages/maps.tsx`](../admin/inertia/pages/maps.tsx) и [`MapComponent`](../admin/inertia/components/maps/MapComponent.tsx):

- стиль грузится с `/api/maps/styles`;
- в `MapComponent` регистрируется протокол `pmtiles://` (`new Protocol()`, `maplibregl.addProtocol`);
- `MapLibre` сам подтягивает источники из стиля;
- стартовый вид по умолчанию — США: `{ longitude: -101, latitude: 40, zoom: 3.5 }` (строки ~45–46). Для «Ковчега» это стоит поменять на Россию или на `fitBounds` установленных ФО.

### 1.4. Хранение, регистрация и подключение скачанных файлов

- Каталог: `storage/maps/pmtiles` (`MapService.mapStoragePath = '/storage/maps'`). Стили/шрифты/спрайты — в `storage/maps/basemaps-assets`, базовый стиль — `storage/maps/nomad-base-styles.json`.
- Раздача: [`MapStaticProvider`](../admin/providers/map_static_provider.ts) и [`MapsStaticMiddleware`](../admin/app/middleware/maps_static_middleware.ts) отдают `storage/maps` как статику; middleware подключён в [`admin/start/kernel.ts`](../admin/start/kernel.ts). URL формирует `MapService.getPublicFileBaseUrl()`.
- Учёт: `InstalledResource` (`resource_type = 'map'`, `resource_id`, `version`, `url`, `file_path`, `file_size_bytes`). Записи создаются либо `RunDownloadJob` (если передан `resourceMetadata`), либо `RunExtractPmtilesJob.onComplete()`, либо `reconcileFromFilesystem()` при старте сервера ([`admin/bin/server.ts`](../admin/bin/server.ts), строки ~39–46).
- Подключение к карте: [`MapService.generateSourcesArray()`](../admin/app/services/map_service.ts) (строки ~546–605) просто перечисляет **все** `.pmtiles` в `storage/maps/pmtiles`, кроме `world.pmtiles`, и добавляет каждый как отдельный vector source. Затем `generateStylesFile()` дублирует для каждого source все слои стиля, у которых есть `source`. То есть установка файла автоматически добавляет его на карту; никакого «включить регион» нет. Отдельно `world.pmtiles` (z0–5, около 15 МБ) вырезается из глобального билда при первом запуске и кладётся под региональные источники, чтобы карта не была серой вне скачанных ФО.
- Атрибуция: константа `PMTILES_ATTRIBUTION` в [`map_service.ts`](../admin/app/services/map_service.ts) (строки ~67–68) сейчас:
  ```html
  <a href="https://github.com/protomaps/basemaps">Protomaps</a> © <a href="https://openstreetmap.org">OpenStreetMap</a>
  ```
  Этого недостаточно для аккуратного ODbL-уведомления: нужны «OpenStreetMap contributors» и ссылка на условия ODbL.
- Загрузка: [`doResumableDownload()`](../admin/app/utils/downloads.ts) (строки ~44–157) делает HEAD, проверяет `Content-Type` по белому списку PMTILES, `Content-Length`, `Accept-Ranges`, качает во временный `.tmp` и умеет продолжать по `Range`. `assertNotPrivateUrl()` в [`validators/common.ts`](../admin/app/validators/common.ts) блокирует loopback/link-local, но **разрешает RFC1918** (10.x, 172.16–31.x, 192.168.x) — это важно для локальных зеркал.
- Обновления: [`KiwixCatalogService`](../admin/app/services/kiwix_catalog_service.ts) для карт делает один запрос к GitHub API:
  ```text
  https://api.github.com/repos/Crosstalk-Solutions/project-nomad-maps/contents/pmtiles
  ```
  и ищет самый новый файл по регулярке `^<resource_id>_(\d{4}-\d{2})\.pmtiles$`. [`CollectionUpdateService.applyUpdate()`](../admin/app/services/collection_update_service.ts) скачивает обновление в `storage/maps/pmtiles`.

### 1.5. Что это значит для задачи с ФО

- Готовые файлы по ФО **вписываются в текущий механизм** без нового протокола: `maps.json` → `downloadCollection()` → `RunDownloadJob` → `storage/maps/pmtiles` → `InstalledResource` → стиль и карта.
- Но есть три ограничения, которые надо учесть в плане:
  1. **Манифест и каталог обновлений зашиты на апстрим.** Локальный `collections/maps.json` сам по себе ни на что не влияет, пока `SPEC_URLS.maps` не переключён на форк (см. 7.1, задача B1).
  2. **Карточка коллекции скачивает всю коллекцию.** Если положить 8 ФО в одну коллекцию, клик скачает все 8 (десятки ГБ). Нужно либо 8 отдельных коллекций по одному ресурсу, либо отдельный пикер с выбором ресурса.
  3. **Каждый установленный файл — отдельный source и полный набор слоёв.** 8 ФО — это 8 source’ов и примерно в 8 раз больше слоёв, чем один регион. Это допустимо, но нужно проверить на слабом железе; 85 файлов по субъектам так делать не стоит.

## 3. Границы ФО и субъектов: источники и лицензии

### 3.1. Требования к геометрии

- Формат: GeoJSON `Polygon`/`MultiPolygon`/`Feature`/`FeatureCollection` в WGS84 (EPSG:4326) — `pmtiles extract --region` принимает именно это.
- Обязательны все острова, эксклавы и полуэксклавы (Калининград, Сахалин, Курилы, Чукотка, Врангель, Новая Земля и т.д.).
- Желательно: топологическая согласованность внутри ФО (субъекты не должны давать щелей и наложений), отсутствие самопересечений, корректная обработка антимеридиана (Чукотка/Врангель).
- Нужно зафиксировать снимок данных: дату OSM/Geofabrik, ID отношений, хеши GeoJSON и исходного билда Protomaps.

### 3.2. OpenStreetMap (основной вариант)

В OSM для России принята иерархия `admin_level`:

- `2` — страна;
- `3` — федеральный округ;
- `4` — субъект РФ (область, республика, край, город федерального значения, автономный округ).

Перед сборкой надо **проверить фактическое наличие 8 отношений** `boundary=administrative`, `admin_level=3` (схема и полнота могут меняться). Например, ЦФО в OSM — это [relation 1029256](https://www.openstreetmap.org/relation/1029256) с тегами `admin_level=3`, `official_status=ru:федеральный округ`, `sqkm=650205`; по таким тегам удобно сверять площадь. Если каких-то округов нет или они неполные, есть два пути:

1. собрать ФО как union полигонов субъектов `admin_level=4` по списку из раздела 2;
2. взять отношения `admin_level=3` и дополнить/исправить их вручную (хуже для воспроизводимости).

Пример запроса Overpass (проверить на актуальной версии API; для больших округов лучше Geofabrik + osmium/GDAL, чтобы не ловить таймауты):

```overpassql
[out:json][timeout:180];
area["ISO3166-1"="RU"][admin_level=2]->.ru;
rel(area.ru)["boundary"="administrative"]["admin_level"="3"];
out tags;
```

Затем по ID отношения:

```overpassql
rel(<ID>);
out geom;
```

Конвертация в GeoJSON — `osmium export` / GDAL OSM driver (`multipolygons`) / `osmtogeojson`. Для повторяемости лучше скачать экстракт России с Geofabrik и обрабатывать локально:

```bash
# пример; имена слоёв/полей зависят от версии GDAL
ogr2ogr -f GeoJSON ru-cfo.geojson russia-latest.osm.pbf multipolygons \
  -where "admin_level='3' AND name='Центральный федеральный округ'"
```

Плюсы OSM:

- та же основа, что у Protomaps Basemap, — границы лучше совпадают с дорогами, водой и береговой линией;
- есть острова, эксклавы, актуальные изменения;
- можно получить и ФО, и субъекты.

Минусы:

- качество волонтёрское, возможны ошибки и разные трактовки спорных территорий;
- отношения бывают сложными (мультиполигоны, анклавы), нужна валидация;
- лицензия ODbL накладывает требования (см. 3.6).

### 3.3. Natural Earth (запасной вариант)

`ne_10m_admin_1_states_provinces` — субъекты (штаты/провинции) мира. ФО как отдельного слоя там нет; ФО можно получить, сгруппировав субъекты по списку и сделав dissolve.

Плюсы:

- public domain, атрибуция не обязательна;
- стабильный, хорошо очищенный dataset;
- удобно, если не хочется связываться с ODbL для границ.

Минусы:

- генерализация 1:10m/1:50m: береговая линия и границы огрублены, возможны щели с тайлами Protomaps;
- нет ФО, нужен маппинг субъектов;
- политика по Крыму/новым территориям отличается от OSM и может не совпадать с ожиданиями;
- данные обновляются реже.

### 3.4. geoBoundaries и другие

- **geoBoundaries** (`gbOpen/RUS/ADM1`) — ADM1, лицензия CC BY 4.0, требуется атрибуция. ФО нет, но субъекты есть; можно dissolve. Качество/дата зависят от версии.
- **GADM** — бесплатно только для некоммерческого использования, для распространения в продукте нужна коммерческая лицензия. **Не использовать.**
- **Официальные границы Росстата/ФО** — часто без явной открытой лицензии; использовать только после письменного разрешения/уточнения условий.
- **atd.openstreetmap.ru** и подобные OSM-производные — ODbL, но зависят от того же OSM; отдельного смысла нет.

### 3.5. Сравнение

| Источник | Лицензия | Атрибуция | ФО напрямую | Точность | Вывод |
|----------|----------|-----------|-------------|----------|-------|
| OSM `admin_level=3/4` | ODbL 1.0 | «© OpenStreetMap contributors», ссылка на copyright | да (3) / субъекты (4) | высокая, но волонтёрская | **основной** |
| Natural Earth admin_1 | public domain | не обязательна, желательна «Made with Natural Earth» | нет, dissolve | средняя (генерализация) | запасной |
| geoBoundaries ADM1 | CC BY 4.0 | обязательна | нет, dissolve | зависит от версии | альтернатива |
| GADM | non-commercial | обязательна | нет | высокая | не использовать |
| Официальные | часто неясна | — | да | высокая | только с разрешением |

### 3.6. Лицензии и атрибуция подробнее

**OpenStreetMap — ODbL 1.0.** Данные можно использовать, в том числе коммерчески, при условии атрибуции и share-alike для производных баз данных. Для картографического «Produced Work» (тайлы, отрендеренная карта) достаточно видимой атрибуции «© OpenStreetMap contributors» со ссылкой на [copyright](https://www.openstreetmap.org/copyright). Если мы распространяем сам GeoJSON границ (файл-базу), это Derivative Database: его нужно предлагать на условиях ODbL и сохранять атрибуцию. Поэтому:

- в стиле/интерфейсе карты — видимая атрибуция OSM;
- в репозитории с GeoJSON — отдельный `LICENSE-ODbL`/`NOTICE` и указание, что границы производны от OSM;
- не смешивать ODbL-геометрию с кодом под Apache 2.0 без явного разделения лицензий.

**Protomaps Basemap** — ODbL Produced Work, требуется атрибуция OpenStreetMap. В документации Protomaps прямо сказано: «distributed as an Open Database License Produced Work (OpenStreetMap attribution required)». Плитки — производная от OSM, поэтому та же атрибуция.

**Natural Earth** — public domain, crediting unnecessary; при желании «Made with Natural Earth».

**geoBoundaries** — CC BY 4.0: нужно указать источник и авторов, ссылку на лицензию; share-alike нет.

**Шрифты/спрайты** — в `project-nomad-maps` шрифты под SIL OFL, спрайты — производные MIT/Tangrams; их лицензии уже лежат в `basemaps-assets`.

Рекомендуемая строка атрибуции в стиле:

```html
<a href="https://github.com/protomaps/basemaps">Protomaps</a> ·
© <a href="https://www.openstreetmap.org/copyright">OpenStreetMap contributors</a> (ODbL)
```

Плюс отдельная страница/раздел «Лицензии карт» с датой билда и ссылкой на исходный билд Protomaps.

### 3.7. Практический рецепт для границ

1. Зафиксировать дату снимка OSM (Geofabrik `russia-latest.osm.pbf` + `osmium fileinfo`, либо timestamp Overpass).
2. Получить 8 отношений `admin_level=3`. Если чего-то нет — собрать union из `admin_level=4` по списку субъектов.
3. Проверить: площадь каждого ФО против таблицы (расхождение > 1–2% — сигнал ошибки), число субъектов, отсутствие дыр/наложений, наличие Калининграда, Сахалина, Курил, Чукотки, островов.
4. Упростить геометрию до разумного размера (например, допуск ~0.001°, примерно 100 м), сохраняя топологию; не упрощать береговую линию до потери островов.
5. Буферизовать наружу на 0.02–0.05° (2–5 км), чтобы не обрезать прибрежные тайлы и подписи. Внутренние границы ФО при этом немного перекроются — это допустимо, но может дать дубли подписей на стыках.
6. Разрезать геометрию по антимеридиану (Чукотка/Врангель) или убедиться, что `pmtiles extract` корректно понимает MultiPolygon с координатами по обе стороны ±180°.
7. Сохранить GeoJSON, `SHA256SUMS`, ID отношений и дату; приложить скрипт сборки.

## 4. Инструмент нарезки

### 4.1. `pmtiles extract`

Используется тот же `go-pmtiles`, что уже стоит в образе (`/usr/local/bin/pmtiles`, версия 1.30.2). Источник — планетарный билд Protomaps (около 120 ГБ), но CLI читает только нужные диапазоны по HTTP, поэтому локально 120 ГБ не нужны.

Пример для одного ФО:

```bash
# 20260211 — пример; подставить актуальный ключ из builds.json
BUILD=20260211
SRC="https://build.protomaps.com/${BUILD}.pmtiles"

pmtiles extract "$SRC" "dist/ru-cfo_2026-02.pmtiles" \
  --region="geojson/ru-cfo.geojson" \
  --maxzoom=15 \
  --download-threads=8 \
  --overfetch=0.2

pmtiles verify "dist/ru-cfo_2026-02.pmtiles"
pmtiles show "dist/ru-cfo_2026-02.pmtiles" --metadata > "dist/ru-cfo_2026-02.metadata.json"
```

`--region` принимает Polygon, MultiPolygon, Feature или FeatureCollection. `--maxzoom` ограничивает верхний зум; `--download-threads` и `--overfetch` ускоряют/батчируют Range-запросы. `--dry-run` показывает оценку размера и числа тайлов без записи файла:

```bash
pmtiles extract "$SRC" /tmp/dry.pmtiles \
  --region="geojson/ru-cfo.geojson" \
  --maxzoom=15 \
  --dry-run
```

Именно эту команду стоит прогнать для каждого ФО на каждом целевом зуме и записать реальные байты. Оценки из раздела 5 — только для планирования.

### 4.2. Пайплайн сборки

1. **Зафиксировать билд.** Взять `builds.json`, выбрать `YYYYMMDD.pmtiles`, записать ключ и дату. Не использовать «latest» в публикации: билд должен быть воспроизводим.
2. **Собрать GeoJSON.** OSM → 8 файлов `ru-cfo.geojson`, `ru-szfo.geojson`, …; проверить геометрию.
3. **Прогнать dry-run** на z10/z12/z14/z15; сохранить отчёт (tiles, bytes) в `build-report.json`.
4. **Нарезать** с `--maxzoom` целевого варианта; проверить `pmtiles verify`.
5. **Посчитать SHA256** и, при желании, BLAKE3; положить в `SHA256SUMS`.
6. **Выгрузить** в хранилище; проверить HEAD, `Content-Length`, `Content-Type`, `Accept-Ranges`.
7. **Обновить `maps.json`** только после того, как URL уже отвечает 200/206: CI `validate-collection-urls` делает HEAD по всем URL.
8. **Записать** в `maps.json` реальный `size_mb` (MiB), версию и максимальный зум в описании/полях.

### 4.3. Имена и версии

Предлагаемая схема:

- ресурс: `ru-cfo`, `ru-szfo`, `ru-yufo`, `ru-skfo`, `ru-pfo`, `ru-urfo`, `ru-sfo`, `ru-dfo`;
- файл: `ru-cfo_2026-02.pmtiles` (версия `YYYY-MM` — как у существующих курируемых карт);
- вариант с другим зумом: `ru-cfo-z12_2026-02.pmtiles`, `ru-cfo-z15_2026-02.pmtiles`, `resource.id` соответственно `ru-cfo-z12`, `ru-cfo-z15`.

Почему `YYYY-MM`, а не `YYYYMMDD`:

- `parseMapFilename()` и `reconcileFromFilesystem()` понимают `_YYYY-MM`;
- `pickNewestMap()` ищет `_YYYY-MM`;
- сравнение версий в `InstalledResource` лексикографическое, для `YYYY-MM` это корректно.

Если нужен ежемесячный билд, но в середине месяца обнаружена ошибка, придётся либо перепубликовать тот же файл под тем же именем (и явно инвалидировать кеш/обновить `spec_version`), либо ввести суффикс (`2026-02b`) и расширить регулярки/сравнение версий. Это отдельное решение; по умолчанию — месячная версия.

### 4.4. Зумы и варианты

Protomaps: каждый дополнительный зум примерно удваивает размер. Практический смысл:

- **z10** — обзорный, области/города; самый маленький, помещается в GitHub Releases.
- **z12** — городской уровень, читаемые названия районов; компромисс для слабых дисков/каналов.
- **z14** — близко к улицам, но без максимальной детализации.
- **z15** — улицы, дома, POI; целевой для «офлайн-карт».

Рекомендация: **z15 — основной вариант**, z12 — облегчённый. z14 как отдельный вариант имеет смысл только если хочется сэкономить половину и не критична детализация; для GitHub Releases он всё равно рискован для СФО/ДФО (около 2,1 ГБ, впритык к лимиту 2 ГиБ).

## 5. Оценка размеров по ФО

### 5.1. Метод (это оценка, не измерение)

Точный размер даёт только `pmtiles extract --dry-run` на конкретном билде. Для планирования использована модель:

1. Число тайлов z15, пересекающих сушу ФО, оценивается по площади и средней широте:
   `N15 ≈ S / (1.495 · cos²φ)`, где `S` — площадь в км², `φ` — средняя широта, `1.495 км²` — площадь тайла z15 на экваторе.
2. Средний размер тайла z15 подобран по пяти штатам США с известными размерами из `maps.json` (Калифорния, Вашингтон, Орегон, Аляска, Гавайи) как функция плотности населения:
   `b ≈ 178 · d^0.589` байт на тайл, где `d` — человек/км². Это грубая регрессия по пяти точкам (R² около 0,8), а не физическая модель.
3. Размер на другом зуме: `size(z) ≈ N15 · b · 2^(z−15)`. Это соответствует правилу Protomaps «каждый дополнительный зум примерно удваивает файл»; для нижних зумов есть погрешность из-за общего оверхеда и дедупликации.

Модель не учитывает: смену стиля/слоёв Protomaps, реальную плотность дорог и зданий, воду, сезонные/политические изменения, дедупликацию одинаковых тайлов, разные версии билда. Поэтому диапазон **±40–50%**; для z15 суммарно это примерно 12–32 ГБ.

### 5.2. Результат

Значения — базовые оценки, округлённые; «ГБ» — примерно 10⁹ байт, не ГиБ.

| ФО | Площадь, тыс. км² | z10 | z12 | z14 | z15 |
|----|------------------:|----:|----:|----:|----:|
| ЦФО | 650 | ~80 МБ | ~330 МБ | ~1,3 ГБ | ~2,6 ГБ |
| СЗФО | 1 687 | ~110 МБ | ~420 МБ | ~1,7 ГБ | ~3,4 ГБ |
| ЮФО | 448 | ~30 МБ | ~120 МБ | ~0,47 ГБ | ~0,94 ГБ |
| СКФО | 170 | ~15 МБ | ~55 МБ | ~0,21 ГБ | ~0,43 ГБ |
| ПФО | 1 037 | ~80 МБ | ~330 МБ | ~1,3 ГБ | ~2,6 ГБ |
| УрФО | 1 818 | ~90 МБ | ~340 МБ | ~1,4 ГБ | ~2,8 ГБ |
| СФО | 4 362 | ~130 МБ | ~530 МБ | ~2,1 ГБ | ~4,2 ГБ |
| ДФО | 6 953 | ~130 МБ | ~530 МБ | ~2,1 ГБ | ~4,3 ГБ |

Интерпретация:

- z12 total ~2,7 ГБ, каждый файл < 1 ГБ — можно раздавать через GitHub Releases.
- z15 total ~21 ГБ; крупнейшие файлы 2,6–4,3 ГБ; в GitHub Releases как один asset они не влезают (лимит 2 ГиБ на файл). Нужно объектное хранилище или разбиение (разбиение потребует кода склейки — не рекомендуется).
- z14 для СФО/ДФО ~2,1 ГБ — близко к лимиту; с учётом погрешности считать «не влезает надёжно».
- Для целевого железа 21 ГБ — заметный, но не катастрофический объём; если диск маленький, z12 как дефолт, z15 — опция.

### 5.3. Как уточнить

На сборочной машине (или в CI с доступом к Protomaps) для каждого ФО и зума:

```bash
pmtiles extract "$SRC" "/tmp/dry-${fo}-z${z}.pmtiles" \
  --region="geojson/${fo}.geojson" \
  --maxzoom="${z}" \
  --dry-run
```

Сохранить stdout/stderr в `build-report.json`, взять оттуда `archive size`/`tiles`, перевести в байты и записать `size_mb = bytes / (1024*1024)`. После этого таблицу 5.2 можно заменить фактическими числами.

## 6. Где хостить файлы

### 6.1. Требования к хостингу

Текущий загрузчик (`doResumableDownload`) ждёт от URL:

- публичный HTTPS (или HTTP для локальной сети);
- `HEAD` с кодом 200;
- `Content-Length`;
- `Content-Type: application/vnd.pmtiles` или `application/octet-stream` (пустой Content-Type тоже обрабатывается как octet-stream);
- `Accept-Ranges: bytes` — иначе не будет докачки;
- стабильный прямой URL (не HTML-страницу);
- отсутствие авторизации для публичных карт;
- желательно `Cache-Control: public, max-age=...` и неизменяемое имя файла.

`assertNotPrivateUrl()` блокирует `localhost`, `127.0.0.1`, link-local и `169.254.x.x`, но **разрешает RFC1918** (10/8, 172.16/12, 192.168/16). То есть локальное зеркало в LAN подходит; `file://` — нет.

### 6.2. Варианты

| Вариант | Для чего годится | Ограничения | Вывод |
|---------|------------------|-------------|-------|
| **GitHub Releases** в отдельном репозитории `kovcheg-maps` | z10/z12, мелкие z14 | **2 ГиБ на asset**; не CDN с SLA; GitHub может быть медленным/недоступным из РФ; счётчик скачиваний/лимиты | хорош как бесплатное зеркало для z10/z12 |
| **Объектное хранилище**: Cloudflare R2, S3, Backblaze B2, Yandex Object Storage, Selectel | z14/z15 и всё остальное | стоимость хранения/трафика; настройка публичного доступа, Content-Type, Range; R2 — zero egress, но доступность из РФ проверить | **основной вариант для z15** |
| **GitHub raw в обычном git-репозитории** | ничего крупного | GitHub блокирует файлы >100 МБ, предупреждает >50 МБ; репозиторий быстро распухает | не использовать |
| **Git LFS** | — | квоты на storage/bandwidth, LFS-указатели вместо файлов, дополнительные зависимости | **не использовать** (явно запрещено) |
| **Локальный носитель / USB** | полностью офлайн-установка | нет автоматического импорта; нужно копировать вручную и перезапускать | допустимо как «офлайн-пакет» |
| **LAN HTTP-сервер** | установка в закрытой сети | URL должен быть доступен с сервера NOMAD; RFC1918 разрешён, loopback — нет | хороший вариант для школы/офиса |
| **Torrent/IPFS** | — | приложение не умеет; нужен новый код | вне scope |

### 6.3. Рекомендуемая схема

1. **Метаданные и сборка** — отдельный репозиторий `kovcheg-maps` (или папка `maps/` в `kovcheg`): `geojson/`, `scripts/`, `SHA256SUMS`, `README`, `LICENSE-ODbL` для границ. Код приложения туда не нужен.
2. **Основные файлы z15** — в объектном хранилище (R2/S3-совместимое), публичный bucket / custom domain, ключи вида `ru-cfo_2026-02.pmtiles`. Это даёт Range, HEAD и большие файлы без лимита 2 ГБ.
3. **Облегчённые z10/z12** — в GitHub Releases того же `kovcheg-maps` как бесплатное зеркало; URL можно указать в `maps.json` для слабых каналов.
4. **Зеркала для РФ** — Yandex Object Storage или Selectel, если GitHub/R2 недоступны/медленны. В `maps.json` сейчас одно поле `url`; либо выбирать основной источник под аудиторию, либо добавить `url_mirror` и логику fallback (отдельная задача).
5. **Целостность** — `SHA256SUMS` рядом с файлами; в идеале проверять хеш после скачивания (сейчас `RunDownloadJob` хеш не проверяет; это отдельная задача).
6. **Локальный носитель** — самый простой путь: скопировать `*.pmtiles` в `storage/maps/pmtiles` на сервере и перезапустить контейнер. `reconcileFromFilesystem()` при старте создаст `InstalledResource` по именам `_YYYY-MM`. Это работает без интернета, но неудобно для конечного пользователя; если нужен UI-импорт — отдельная задача (см. 7.13).

### 6.4. Как это ложится на текущий механизм

Ничего нового в протоколе не нужно:

- `maps.json` → `resource.url` (прямой HTTPS);
- `downloadCollection()` → `RunDownloadJob` → `storage/maps/pmtiles`;
- `InstalledResource` → `generateSourcesArray()` → стиль → MapLibre;
- `size_mb` → карточка коллекции;
- `version`/имя файла → обновления и reconcile.

Единственное, что придётся сделать, — переключить манифест и каталог обновлений на форк/новый источник (см. 7.1–7.2).

### 6.5. Про лимит GitHub

GitHub Releases: каждый файл релиза должен быть меньше **2 ГиБ**. Этого достаточно для z10/z12 и большинства z14, но **не** для z15 СЗФО/ПФО/УрФО/СФО/ДФО (по оценке 2,6–4,3 ГБ). GitHub raw в git — ещё жёстче: файлы >100 МБ не принимаются. Поэтому:

- z12 — GitHub Releases;
- z15 — объектное хранилище;
- Git LFS — нет.

Ссылки: [GitHub Docs — About releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases), [Protomaps Downloads](https://docs.protomaps.com/basemaps/downloads).

### 7.2. P0. Починить каталог обновлений карт

## 8. Риски и открытые вопросы

### 8.1. Риски

| Риск | Вероятность | Влияние | Что делать |
|------|-------------|---------|------------|
| Манифест/каталог зашиты на апстрим — правки не доезжают | высокая | блокер | задачи 7.1–7.2 до данных |
| Политическая трактовка Крыма/новых территорий | высокая | высокое | решение владельца, дисклеймер, отдельный слой/вариант |
| Антимеридиан (Чукотка, Врангель) ломает полигон | средняя | высокое | тест MultiPolygon, разрезать по ±180°, визуальная проверка |
| Лимит GitHub 2 ГиБ | высокая для z15 | среднее | R2/S3 для z15, GitHub только z10/z12 |
| 21 ГБ не влезает на целевой диск | средняя | высокое | z12 как дефолт, z15 опция, предупреждение о месте |
| 8 sources × слои тормозят карту | средняя | среднее | тест, буфер/мерж, лимит источников |
| OSM-границы расходятся с билдом Protomaps | средняя | низкое | брать снимок OSM рядом с датой билда, визуальная проверка |
| ODbL/атрибуция оформлены неверно | низкая | высокое | атрибуция в стиле + LICENSE-ODbL для GeoJSON |
| Ежемесячная версия/пересборка в том же месяце | средняя | среднее | регламент версий, расширение regex при необходимости |
| GitHub/R2 медленно/недоступно из РФ | средняя | высокое | зеркало Yandex/Selectel, LAN/USB |
| Нет проверки SHA256 после скачивания | средняя | среднее | отдельная задача, `SHA256SUMS` |
| Локальный импорт неудобен | высокая | низкое | docs + опциональный import API |
| Подписи `name:ru` есть не для всех объектов | средняя | низкое | проверить на тестовых городах, дополнить стиль/данные |
| Ошибки в границах (дыры, потерянные острова) | средняя | высокое | валидация площади/топологии, тестовые точки |

### 8.2. Открытые вопросы владельцу

## Приложение B. Минимальный чек-лист публикации одного ФО

- [ ] OSM-снимок зафиксирован, ID отношений записаны.
- [ ] GeoJSON валиден, площадь сходится с таблицей, острова/эксклав/антимеридиан проверены.
- [ ] `pmtiles extract --dry-run` выполнен на целевом зуме, байты записаны.
- [ ] Файл нарезан, `pmtiles verify` проходит.
- [ ] `SHA256SUMS` создан.
- [ ] Файл загружен, HEAD 200, `Content-Length` есть, `Content-Type` корректный, `Accept-Ranges: bytes`.
- [ ] `size_mb` в `maps.json` соответствует реальному размеру.
- [ ] `version`/имя файла — `YYYY-MM`.
- [ ] `validate-collection-urls` проходит.
- [ ] На чистом инстансе скачивание идёт, карта открывается, атрибуция видна.
- [ ] Удаление файла и повторное скачивание работают.
