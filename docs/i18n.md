# Перевод интерфейса (i18n)

Модуль перевода живёт в `admin/inertia/i18n/` и не требует новых npm-зависимостей.

```
admin/inertia/i18n/
├── index.ts            # Locale, translate(), плюрал, localStorage, Intl-хелперы
├── I18nProvider.tsx    # React-контекст и хук useT()
└── locales/
    ├── en.ts           # английский словарь — источник типа ключей
    └── ru.ts           # русский словарь, обязан повторять набор ключей en
```

## Быстрые правила

- Весь видимый текст — только через `t('namespace.key')`, включая `title`, `placeholder`, `aria-label`, `alt`, `<Head title>` и тексты уведомлений/подтверждений.
- `en.ts` — эталон набора ключей; `ru.ts` должен повторять его рекурсивно.
- Не переводите данные: имена приложений, моделей, препаратов, файлов, коллекций, внешние бренды, URL, технические литералы (`NOMAD.md`, `RESET`, `OLLAMA_HOST`, единицы `MB/s`, названия лицензий).
- В русском тексте продукт называется **«Ковчег»**, а не NOMAD (исключения: `NOMAD.md`, упоминание апстрима Project NOMAD).
- Новые строки сначала добавляйте в `en.ts`, затем в `ru.ts` — TypeScript покажет пропуск.

## Использование в React

```tsx
import { useT } from '~/i18n/I18nProvider'

export default function SaveButton() {
  const { t, locale, setLocale, formatDate, formatNumber } = useT()

  return (
    <button onClick={() => setLocale(locale === 'ru' ? 'en' : 'ru')}>
      {t('common.save')}
    </button>
  )
}
```

`useT()` возвращает:

- `t(key, params?)` — перевод с подстановкой параметров;
- `locale` — текущий язык (`'ru' | 'en'`);
- `setLocale(locale)` — переключение языка, сохранение в `localStorage` и обновление `<html lang>`;
- `formatDate(value, options?)` / `formatNumber(value, options?)` — форматирование через `Intl` с локалью `ru-RU` / `en-US`.

`I18nProvider` подключён в `admin/inertia/app/app.tsx`. Хук можно вызывать только внутри провайдера. Переключатель языка — `components/LanguageSwitcher.tsx`, он выведен в футере.

## Параметры

Параметры записываются в строке в фигурных скобках:

```ts
// en.ts
welcome: 'Welcome, {name}!'

// ru.ts
welcome: 'Добро пожаловать, {name}!'
```

```ts
t('common.welcome', { name: 'Иван' }) // «Добро пожаловать, Иван!»
```

Если параметр не передан, плейсхолдер остаётся в строке как есть. Набор `{x}` в `ru.ts` должен совпадать с набором в `en.ts` — это проверяет unit-тест.

## Плюрал

Для строк с числом используйте объект с формами и передавайте `count`:

```ts
// en.ts
files: { one: '{count} file', few: '{count} files', many: '{count} files', other: '{count} files' }

// ru.ts
files: { one: '{count} файл', few: '{count} файла', many: '{count} файлов', other: '{count} файла' }
```

```ts
t('common.files', { count: 1 })  // 1 файл
t('common.files', { count: 2 })  // 2 файла
t('common.files', { count: 5 })  // 5 файлов
t('common.files', { count: 21 }) // 21 файл
```

Форма выбирается через `Intl.PluralRules`: для русского — `one` / `few` / `many` / `other`, для английского — `one` / `other`. В русском словаре у каждого плюрального ключа обязательны все четыре формы.

## Форматирование

### formatBytes

`formatBytes(bytes, decimals = 2, locale = getCurrentLocale())` из `admin/inertia/lib/util.ts`.

- `ru`: `1,5 КБ`, `1,2 МБ`, `1 ГБ`;
- `en`: `1.5 KB`, `1.2 MB`, `1 GB`.

В компонентах локаль можно не передавать: по умолчанию берётся язык из `I18nProvider`. Для явного форматирования передайте `formatBytes(value, 2, 'ru')`.

### formatDate / formatNumber

```ts
import { formatDate, formatNumber } from '~/i18n'

formatDate('ru', new Date(), { dateStyle: 'long' })
formatNumber('ru', 1234.5) // 1 234,5
```

В React используйте обёртки из `useT()`:

```tsx
const { formatDate, formatNumber } = useT()
formatDate(new Date(), { dateStyle: 'short' })
formatNumber(1234.5, { maximumFractionDigits: 1 })
```

## Серверные сообщения

Сервер (`admin/app/**`) остаётся англоязычным. Известные английские сообщения переводятся на клиенте в `admin/inertia/lib/serverMessages.ts`:

- `SERVER_MESSAGE_KEYS` — точные строки, например `'Setting updated successfully'`;
- `SERVER_MESSAGE_PATTERNS` — регулярные выражения для динамических сообщений с именами служб, коллекций и версиями.

```ts
import { localizeServerMessage } from '~/lib/serverMessages'

const { t } = useT()
setError(localizeServerMessage(error.message, t))
```

`NotificationProvider` уже вызывает `localizeServerMessage`, поэтому уведомления переводятся автоматически. Неизвестные сообщения возвращаются как есть — это нужно для диагностики.

Чтобы перевести новое серверное сообщение:

1. Добавьте ключ в `serverMessages.*` в `en.ts` и `ru.ts`.
2. Добавьте английскую строку в `SERVER_MESSAGE_KEYS` или шаблон в `SERVER_MESSAGE_PATTERNS`.
3. Для динамической строки используйте именованные группы/параметры (`{name}`, `{version}`) и проверьте плюрал, если есть число.

## Uppy

Строки загрузчика Uppy лежат в `admin/inertia/lib/uppyLocale.ts`. `getUppyLocale(locale)` возвращает русский словарь для `ru` и `undefined` для `en` — тогда Uppy использует свои английские строки.

- Uppy использует числовые формы плюрала: `0` — one, `1` — few, `2` — many. Их выбирает `russianPlural()` через `Intl.PluralRules`.
- Плейсхолдеры Uppy записываются как `%{file}`, `%{size}`, `%{smart_count}` — не путайте с `{name}` в основном словаре.
- Словарь подключён в `components/file-uploader/index.tsx` и `components/ZimUploader/index.tsx`; при смене языка вызывается `uppy.setOptions({ locale: getUppyLocale(locale) })`.

## Как добавить новый язык

1. Создайте `locales/xx.ts` на основе `en.ts`, сохранив все ключи и формы плюрала; типизируйте объект через `TranslationShape<EnDictionary>`.
2. В `i18n/index.ts` добавьте код в `Locale`, `SUPPORTED_LOCALES`, `INTL_LOCALES`, `pluralRules` и `dictionaries`.
3. В `components/LanguageSwitcher.tsx` добавьте пункт в `LANGUAGE_OPTIONS`.
4. Если нужен перевод Uppy, добавьте ветку в `getUppyLocale()`.
5. Проверьте `npm run typecheck` и unit-тесты. Новый словарь должен проходить те же проверки ключей, плейсхолдеров, плюралов и пустых строк.

## Фолбэк

Порядок поиска:

1. выбранный язык;
2. английский словарь;
3. сам ключ, если строки нет нигде.

Предупреждение в консоль (`console.warn`) выводится только в development-сборке.

## Проверка

```bash
cd admin
npm run typecheck
node --import ts-node-maintained/register/esm --test --test-isolation=none \
  tests/unit/i18n.spec.ts tests/unit/i18n_format.spec.ts tests/unit/i18n_integrity.spec.ts
```

`i18n_integrity.spec.ts` проверяет:

- рекурсивное совпадение ключей `ru` и `en`;
- совпадение набора `{x}`-плейсхолдеров;
- наличие `one` / `few` / `many` / `other` у русских плюралов;
- отсутствие пустых строк в `ru.ts`;
- что продукт в `ru.ts` называется «Ковчег», а NOMAD остаётся только в `NOMAD.md`, `project-nomad` и упоминании апстрима Project NOMAD;
- что все статические ключи из `t('...')` в `admin/inertia/**` есть в обоих словарях.
