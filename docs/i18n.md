# Перевод интерфейса (i18n)

Модуль перевода живёт в `admin/inertia/i18n/` и не требует новых npm-зависимостей.

```
admin/inertia/i18n/
├── index.ts            # Locale, translate(), плюрал, localStorage, Intl-хелперы
├── I18nProvider.tsx    # React-контекст и хук useT()
└── locales/
    ├── en.ts           # английский словарь — источник типа ключей
    └── ru.ts           # русский словарь, обязан повторять набор ключей en
```

## Как добавить строку

1. Добавьте ключ в `locales/en.ts`. Ключи — английские, в camelCase, с точкой между namespace и ключом: `common.save`, `errors.network`.
2. Добавьте тот же ключ в `locales/ru.ts`. Если ключ пропущен, `npm run typecheck` в `admin` завершится ошибкой: тип русского словаря строится из `en.ts`.
3. Используйте ключ в компоненте через `t('common.save')`.

Не добавляйте текст интерфейса прямо в JSX — только через `t()`.

## Использование в React

```tsx
import { useT } from '~/i18n/I18nProvider'

export default function SaveButton() {
  const { t, locale, setLocale, formatDate, formatNumber } = useT()

  return (
    <button onClick={() => setLocale(locale === 'ru' ? 'en' : 'ru')}>
      {t('common.save')}
    </button>
  )
}
```

`useT()` возвращает:

- `t(key, params?)` — перевод с подстановкой параметров;
- `locale` — текущий язык (`'ru' | 'en'`);
- `setLocale(locale)` — переключение языка, сохранение в `localStorage` и обновление `<html lang>`;
- `formatDate(value, options?)` / `formatNumber(value, options?)` — форматирование через `Intl` с локалью `ru-RU` / `en-US`.

`I18nProvider` уже подключён в `admin/inertia/app/app.tsx`. Хук можно вызывать только внутри провайдера.

## Параметры

Параметры записываются в строке в фигурных скобках:

```ts
// en.ts
welcome: 'Welcome, {name}!'

// ru.ts
welcome: 'Добро пожаловать, {name}!'
```

```ts
t('common.welcome', { name: 'Иван' }) // «Добро пожаловать, Иван!»
```

Если параметр не передан, плейсхолдер остаётся в строке как есть.

## Плюрал

Для строк с числом используйте объект с формами и передавайте `count`:

```ts
// en.ts
files: { one: '{count} file', few: '{count} files', many: '{count} files', other: '{count} files' }

// ru.ts
files: { one: '{count} файл', few: '{count} файла', many: '{count} файлов', other: '{count} файла' }
```

```ts
t('common.files', { count: 1 })  // 1 файл
t('common.files', { count: 2 })  // 2 файла
t('common.files', { count: 5 })  // 5 файлов
t('common.files', { count: 21 }) // 21 файл
```

Форма выбирается через `Intl.PluralRules`: для русского — `one` / `few` / `many` / `other`, для английского — `one` / `other`. Набор ключей у `en` и `ru` должен совпадать, поэтому в обоих словарях перечислены все четыре формы.

## Фолбэк

Порядок поиска:

1. выбранный язык;
2. английский словарь;
3. сам ключ, если строки нет нигде.

Предупреждение в консоль (`console.warn`) выводится только в development-сборке.

## Правила

- Ключи — по-английски, иерархические (`common.save`), без русских слов в ключах.
- `locales/en.ts` — источник типа ключей и эталон набора строк.
- `locales/ru.ts` обязателен: русский перевод должен быть естественным, без канцелярита.
- Для новых строк сначала обновите `en.ts`, затем `ru.ts` — так TypeScript сразу покажет пропуск.
- Язык хранится в `localStorage` под ключом `kovcheg.locale`. Доступ к хранилищу и DOM обёрнут в `try/catch`, поэтому модуль безопасен в средах без `localStorage`.
- Переключатель `components/LanguageSwitcher.tsx` пока не встроен в страницы — это будет сделано в задаче 5.1.

## Проверка

```bash
cd admin
npm run typecheck
node --import ts-node-maintained/register/esm --test --test-isolation=none tests/unit/i18n.spec.ts
```

Тесты проверяют совпадение наборов ключей, подстановку параметров, русский и английский плюрал, фолбэк на `en` и на сам ключ, а также Intl-хелперы.
